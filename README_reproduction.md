# Reproducibility materials

For **Compact Visuotactile World Models for Lifting: Prediction, Reward Alignment, and Force Constraints**.

This archive contains the scientific training/evaluation code, fixed data and evaluation manifests, and numerical results. It does **not** contain raw tactile images, simulator trajectory arrays, model weights, earlier manuscripts, synthetic smoke-test results, or document-building tools. Those omitted arrays and weights can be regenerated with the commands below. Reported results have not been changed during packaging.

`outputs/` contains executable code and the public-data download manifest. `recorded/outputs/` contains the original numerical results with host paths converted to relative references. Keep `recorded/` unchanged; fresh experiments write to `outputs/` and `work/`.

## Environments

Use the versions recorded in `ENVIRONMENT.json` as the reference execution environment. Training used Python 3.14.2, CUDA-enabled PyTorch 2.14.0+cu130, and an RTX 5090 Laptop GPU. Simulation used Python 3.12.14, robosuite 1.5.1 and MuJoCo 3.3.7. Analysis used NumPy, Pillow and Matplotlib. No pretrained model is downloaded.

Separate Python environments were used because the simulator and training runtimes differed. The commands below use `python` from the environment named above each block. For simulator policy execution, replace `PATH_TO_TRAIN_PYTHON` with the Python executable in your training environment. The copied matrix runners require this argument rather than embedding an author's machine path.

The simulation imports robosuite, mujoco, NumPy, SciPy, imageio and GLFW. Use a working GLFW/OpenGL context; the recorded renderer is GLFW. Cross-platform bitwise equality is not claimed. `sim_adapter.py` optionally searches `work/sim_deps` before the active environment and stores temporary/cache files under `work/`; installing dependencies in the active simulator environment is sufficient.

## 1. Public GelSight force study

In the analysis/data environment:

```text
python outputs/research/download_public_data.py
python outputs/research/prepare_public_force_data.py --data work/data/gelsight_force --out work/gpu_force_prepared --audit outputs/research/real_force_data_audit.json
```

The downloader defaults to the fixed revision `136db55485b6501605b1d2648ce0fe44740e302e` and the included 50-file SHA-256 manifest. The download is approximately 2.333 GB; source data are CC BY-NC 4.0. Labels in this release are already Newtons with positive normal force. Conversion retains the official same-sample image/force pairing, with no extra division by 1,000 or normal-force sign flip.

In the CUDA training environment:

```text
python outputs/research/train_force_envelopes.py --data work/gpu_force_prepared --out outputs/research --epochs 30 --batch-size 256 --seeds 17 29 43
```

Then in the analysis environment:

```text
python outputs/research/analyze_force_envelopes.py
```

The split seed is 314159 and the split unit is a whole loading/shear trajectory. Flat/sharp shape-shift evaluations and the fixed -5/0/+5-frame sensitivity analysis are exploratory. The supplied slip labels are friction-cone derived, not independent slip ground truth.

## 2. Simulator dataset and world models

In the simulator environment, generate all 160 episodes in one run:

```text
python outputs/simulation/generate_dataset.py --out outputs/simulation --episodes 160 --start 0
python outputs/simulation/audit_dataset.py
```

The data split is 80 train, 16 validation, 24 calibration, 20 ID test and 20 OOD test episodes. The collection seeds begin at 20270915. Data arrays are generated under `outputs/simulation/episodes/`.

In the CUDA training environment:

```text
python outputs/world_model/train.py --data outputs/simulation/episodes --output outputs/world_model/runs --variants vision visuotactile --seeds 0 1 2 --epochs 25 --batch-size 64 --train-stride 3 --eval-stride 5 --device cuda
```

**The reported training stride is 3; omitting this option uses the script default of 1 and does not reproduce the reported configuration.** The model has 652,157 parameters. It uses three observation frames and five autoregressive future steps. AdamW uses learning rate 3e-4 and weight decay 1e-4; EMA update rate is .01 and gradient clipping is 20. The loss is force + height + peak + .25(support + contact) + .5 reward + .5 RGB + 20 latent consistency. Training supervision includes the current state; the future latent consistency term uses only the five predicted future states.

The tactile channel order is `[left normal, left signed shear-up, left signed shear-cross, right normal, right signed shear-up, right signed shear-cross]`, in N. At state t+1, `substep_normal_peak` summarizes the 25 physics substeps caused by action t. Object/contact/peak labels are supervision, not encoder inputs.

## 3. First control cohort

Train nine actor runs in the CUDA environment, including vision and visuotactile BC-initialized RL and three visuotactile margin variants:

```text
python outputs/world_model/run_pilot_matrix.py --runs outputs/world_model/runs --out outputs/world_model/rl
```

Each actor run performs 1,000 BC and 1,500 imagined updates with batch size 256, horizon five, discount .95, actor learning rate 2e-4 and critic learning rate 3e-4. The frozen world-model training data supply 3,520 encoded starts. The force budget is 8 N per finger and the behavior-prior weight is 2.

In the simulator environment, evaluate both baselines and the fifteen learned policies on the same 20 new environment seeds:

```text
python outputs/simulation/evaluate_controller.py --controller script --episodes 20 --seed-start 20281000 --out outputs/simulation/evaluation_main/script --save-trajectories
python outputs/simulation/evaluate_controller.py --controller force_feedback --episodes 20 --seed-start 20281000 --out outputs/simulation/evaluation_main/force_feedback --save-trajectories
python outputs/simulation/run_policy_matrix.py --gpu-python PATH_TO_TRAIN_PYTHON --out outputs/simulation/evaluation_main --runs outputs/world_model/runs --actors outputs/world_model/rl
python outputs/simulation/audit_control_pairing.py --root outputs/simulation/evaluation_main
```

## 4. Exploratory matched reward follow-up

This experiment was introduced after observing the first cohort's failures. Its twenty new seeds are 20291000–20291019. Original native-reward policies are re-evaluated on those same new environments; no comparison mixes the two cohorts.

In the CUDA environment:

```text
python outputs/world_model/run_goal_aligned_matrix.py --out outputs/world_model/rl_goal_aligned
```

Only the task-reward term changes to `clip(predicted_relative_height / .10, 0, 1)`; the native-reward and height-reward actors share the same world-model checkpoint and BC initialization. In the simulator environment:

```text
python outputs/simulation/run_goal_aligned_matrix.py --gpu-python PATH_TO_TRAIN_PYTHON --out outputs/simulation/evaluation_goal_aligned --runs outputs/world_model/runs --bc-actors outputs/world_model/rl --new-actors outputs/world_model/rl_goal_aligned
python outputs/simulation/audit_control_pairing.py --root outputs/simulation/evaluation_goal_aligned
```

This evaluates 17 controllers: two baselines, three BC policies, six native-reward policies and six height-reward policies. Use fresh output directories for new experiments. Do not append results from modified settings to either cohort.

## 5. Executed-action diagnostics and analysis

In the CUDA environment:

```text
python outputs/world_model/evaluate_executed_forecasts.py --evaluations outputs/simulation/evaluation_main --out outputs/world_model/executed_forecasts
python outputs/world_model/evaluate_executed_forecasts.py --evaluations outputs/simulation/evaluation_goal_aligned --out outputs/world_model/executed_forecasts_goal_aligned
```

These diagnostics supply the future actions actually executed. They do not claim online planning forecasts without knowledge of those subsequent actions. Original calibration remains frozen.

In the analysis environment:

```text
python outputs/world_model/analyze_results.py --controls outputs/simulation/evaluation_main --output outputs/world_model/analysis --executed-forecasts outputs/world_model/executed_forecasts
python outputs/world_model/analyze_results.py --controls outputs/simulation/evaluation_goal_aligned --output outputs/world_model/analysis_goal_aligned --executed-forecasts outputs/world_model/executed_forecasts_goal_aligned
```

The analysis rejects mixing the two formal control cohorts. It resamples full environment episodes, with the same draw used across fixed training seeds; three policies on ten ID conditions are not thirty independent environments. Fixed-policy bootstrap intervals do not include uncertainty over arbitrary retraining. Per-policy counts and Wilson intervals are also retained.

## Metric definitions and scope

- Strict lifting means relative object height ≥0.10 m at **ten consecutive 20-Hz observations** before lowering. It is a discrete observation counter, not a continuously verified 0.5-second dwell. The ten samples' first-to-last spacing is 0.45 seconds.
- Only vertical motion and gripper rate vary during actions 44–134; five other action coordinates are zero for every controller. A shared scripted approach precedes this interval and shared lowering starts at action 135.
- Joint force-budget success additionally requires every per-finger normal-force peak over all 25 substeps of every action in the complete 150-action episode to be ≤8 N. Setup and lowering are included; failed grasps remain in the denominator.
- OOD mass/friction settings are a force-budget compatibility stress group. The ideal horizontal friction-only static pinch cannot support these loads within 8 N per finger. This is not a proof of infeasibility for every possible geometric or dynamic MuJoCo strategy.
- The public real tactile study is separate from the simulator branch. Simulated contact-force aggregates are not real optical tactile sensor images. No transfer of the public CNN to the control policy or physical-robot execution is demonstrated.
